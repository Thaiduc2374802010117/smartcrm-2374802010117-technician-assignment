# API Documentation – Smart CRM, flow L4 (Technician assignment & appointments), track SE

Base URL: `http://localhost:3000` · Version 1.0.0 · Interactive docs: `http://localhost:3000/docs` · OpenAPI: `docs/openapi.json`  
Examples below are REAL request/response pairs generated by `python -m scripts.gen_api_docs` on the sample data (2026-11-10 09:40).

## Conventions
- JSON in/out, UTF-8. Times are ISO 8601; a time without offset is read as Vietnam time (+07:00).
- Every error uses one shape: `{"error": {"code": "...", "message": "...", "fields": {...}}}`. Database unavailable → `503 DATABASE_UNAVAILABLE`; unexpected error → `500 INTERNAL_ERROR` without internal details.
- **Authentication:** the prototype simulates login (out of scope, W8). Every `/api/*` call sends `X-Employee-Id` (1…2⁶³−1), `X-Role` (`QUAN_LY`) and `X-Center-Id` (1…2³¹−1). Missing/out-of-range → 401; data of another centre → 403.
- 13 business endpoints (E1–E5, E9–E16; E6–E8 postponed, see docs/thay-doi-thiet-ke.md TD-09) + `/health`.

1. **Description:** Liveness and database check (used by the docker compose healthcheck).
2. **Authentication:** None.
3. **Parameters:** None.
4. **Success response:** `200 {"status":"ok","db":"up"}`
5. **Errors:**

| HTTP | code | when |
|---|---|---|
| 503 | – | `{"status":"degraded","db":"down"}` – database unreachable; no connection details are returned |

6. **Limits:** None.
7. **Example (real run):**

```http

```

Response `200`:

```json

  "status": "ok",
  "db": "up"
}
```

## GET /api/tickets  (E1)
1. **Description:** List tickets of the caller's service centre, ordered by committed due date ascending; flags `is_due_soon` (< 24 h) and `is_overdue`.
2. **Authentication:** Required – headers `X-Employee-Id`, `X-Role: QUAN_LY`, `X-Center-Id` (simulated login, see §Authentication).
3. **Parameters:** Query: `status` (default `MOI`; MOI, DA_PHAN_CONG, DANG_XU_LY, CHO_LINH_KIEN, HOAN_TAT, DA_DONG, DA_HUY) · `category_id` int · `priority` CAO/TRUNG_BINH/THAP · `page` ≥ 1 (default 1) · `size` 1–100 (default 20).
4. **Success response:** `200 {page, size, total, items[]}`
5. **Errors:**

| HTTP | code | when |
|---|---|---|

6. **Limits:** Max 100 items per page.

## POST /api/tickets/{ticket_id}/assignment  (E3)
1. **Description:** Assign a NEW ticket to a technician; writes one status-log row in the same transaction. Concurrent requests: exactly one succeeds (conditional UPDATE … WHERE status='MOI', NFR3).
2. **Authentication:** Required – headers `X-Employee-Id`, `X-Role: QUAN_LY`, `X-Center-Id` (simulated login, see §Authentication).
3. **Parameters:** Path: `ticket_id` int. Body: `{"technician_id": int > 0}`.
4. **Success response:** `201 {ticket_id, ticket_code, status, technician_id, assigned_at, status_log{}}`
5. **Errors:**

| HTTP | code | when |
|---|---|---|
| 400 | VALIDATION_FAILED | missing/invalid technician_id, malformed JSON |
| 404 | NOT_FOUND | ticket or technician not found |
| 409 | INVALID_STATE | ticket is no longer MOI (already assigned) |
| 422 | TECHNICIAN_NOT_ELIGIBLE / CATEGORY_REQUIRED | QT-08 not met |
| 401 | UNAUTHENTICATED | missing/invalid identity headers |
| 403 | FORBIDDEN | wrong role, or resource of another service centre (QT-14) |

6. **Limits:** One technician per ticket (QT-07).
7. **Example (real run):**

```http
POST /api/tickets/1/assignment
X-Employee-Id: 3
X-Role: QUAN_LY
X-Center-Id: 2
Content-Type: application/json

{"technician_id": 2}
```

Response `201`:

```json
{
  "ticket_id": 1,

  "status": "DA_PHAN_CONG",
```

## POST /api/tickets/{ticket_id}/appointments  (E5)
1. **Description:** Book a device hand-over (GIAO_MAY) or return (TRA_MAY) appointment for the technician currently holding the ticket.
2. **Authentication:** Required – headers `X-Employee-Id`, `X-Role: QUAN_LY`, `X-Center-Id` (simulated login, see §Authentication).
3. **Parameters:** Path: `ticket_id` int. Body: `{appointment_type: GIAO_MAY|TRA_MAY, start_at, end_at, note?}` (ISO 8601).
4. **Success response:** `201 {appointment_id, ticket_id, technician_id, appointment_type, start_at, end_at, status: DA_HEN, note, created_by}`
5. **Errors:**

| HTTP | code | when |
|---|---|---|
| 400 | VALIDATION_FAILED | QT-L4-03: 15–120 min, 08:00–18:00, Mon–Sat, in the future; note ≤ 255 chars |
| 404 | NOT_FOUND | ticket not found |
| 409 | APPOINTMENT_CONFLICT | overlaps another DA_HEN appointment (QT-L4-02); `fields.suggested_start_at` |
| 409 | INVALID_STATE | ticket is not open |
| 422 | TICKET_NOT_ASSIGNED | ticket has no technician (QT-L4-04) |
| 401 | UNAUTHENTICATED | missing/invalid identity headers |
| 403 | FORBIDDEN | wrong role, or resource of another service centre (QT-14) |

6. **Limits:** Overlap also blocked by a database EXCLUDE constraint.
7. **Example (real run):**

```http
POST /api/tickets/1/appointments
X-Employee-Id: 3
X-Role: QUAN_LY
X-Center-Id: 2
Content-Type: application/json

{"appointment_type": "TRA_MAY", "start_at": "2026-11-12T09:00:00+07:00", "end_at": "2026-11-12T09:30:00+07:00", "note": "Customer picks up before noon"}
```
